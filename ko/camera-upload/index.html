카메라 업로드(베타): iPhone 사진을 개인 Plex 서버에 백업하기

2026년 11월 26일 업데이트 · 설정 시간 약 10분

카메라 업로드는 기기가 집 Wi-Fi에 연결되어 있는 동안 iPhone이나 iPad의 사진과 비디오를 집에 있는 서버로 백업합니다. 백업한 항목은 다른 모든 항목과 함께 Plex와 Phlix에 표시됩니다. 클라우드도 저장 공간 구독도 필요 없습니다. 사진은 개인 서버로 전송될 뿐, 다른 누구에게도 전송되지 않습니다.

카메라 업로드는 베타 기능입니다. Phlix 1.0.21 이상에 포함되어 있습니다. App Store에서 아직 이 버전을 받을 수 없다면 출시 준비 중인 것입니다.

카메라 업로드는 두 부분으로 이루어져 있습니다. iPhone이나 iPad의 Phlix 앱이 카메라 롤을 읽습니다. 서버에 설치하는 작은 무료 프로그램인 카메라 업로드 도우미가 사진을 받아 Plex 사진 라이브러리의 폴더에 저장합니다. 도우미는 Docker 컨테이너 하나로 되어 있습니다.

  • 집에서만 작동합니다. Phlix는 집 Wi-Fi에서만 업로드하고, 그 밖의 곳에서는 업로드하지 않습니다. 셀룰러 데이터로는 절대 업로드하지 않습니다.
  • 개인 서버로만 전송합니다. 사진은 암호화되어 휴대폰에서 서버로 바로 전송됩니다. Phlix에는 사진이 한 장도 전송되지 않습니다.
  • 복사만 합니다. 휴대폰에 있는 항목은 절대 삭제되거나 변경되지 않습니다.

배경: Plex 자체 Camera Upload 기능의 종료

Plex에는 2014년부터 자체 Camera Upload 기능이 있었습니다. 2021년 3월, Plex는 포럼을 통해 이 기능의 지원을 종료한다고 발표했으며, 제거 시점은 2021년 6월로 예정되어 있었습니다(Plex의 발표, 보관된 사본).

Phlix의 카메라 업로드는 이 아이디어를 iPhone과 iPad에서 다시 살려 냅니다. Phlix는 Plex Media Server와 함께 작동하는 독립 앱이며, Plex에서 만든 앱이 아닙니다. 전체 이야기(영어).

필요한 것

  • 사진 라이브러리가 있는 Plex Media Server: Docker 20.10 이상을 실행하는 컴퓨터나 NAS에 있어야 합니다. Linux, Docker Desktop을 설치한 Mac 또는 Windows PC, Synology(Container Manager, DSM 7.2 이상), Unraid, TrueNAS SCALE 24.10 이상에서 사용할 수 있습니다. Docker는 다른 프로그램을 컨테이너라는 닫힌 상자 안에서 실행하는 무료 프로그램입니다. Intel, AMD, Arm 프로세서에서 모두 작동합니다.
  • Phlix 1.0.21 이상: iPhone 또는 iPad에 설치되어 있어야 합니다. App Store에서 아직 이 버전을 받을 수 없다면 출시 준비 중인 것입니다.
  • 휴대폰과 서버가 같은 집 네트워크에 있어야 합니다.

도우미는 무료입니다. 앱에서는 처음 100회의 업로드가 무료이며, 나머지는 Phlix Pro가 업로드합니다. 카메라 업로드가 베타인 동안에는 대체할 수 없는 항목을 따로 백업해 두세요. 베타에서 되는 것과 안 되는 것(영어).

1단계: 도우미 설치하기

휴대폰으로 보고 계신가요? 1단계는 서버에서 진행합니다. 명령어를 복사할 수 있도록 컴퓨터에서 이 페이지를 여세요.

Plex Media Server를 실행하는 컴퓨터에서 한 번만 하면 됩니다. 먼저 휴대폰의 사진이 들어갈 폴더인 업로드 폴더를 정하세요. 이 폴더는 반드시 Plex 사진 라이브러리 중 하나에 포함된 폴더 안에 있어야 합니다. 그렇지 않으면 Plex에 사진이 표시되지 않습니다. 라이브러리 폴더가 /mnt/media/Photos라면 /mnt/media/Photos/Camera Uploads를 사용하는 것이 좋습니다.

라이브러리의 폴더를 확인하려면 브라우저에서 Plex를 열고 설정 › 관리 › 라이브러리로 이동한 다음, 사진 라이브러리에서 라이브러리 편집을 선택하고 폴더 추가를 선택하세요.

Plex도 Docker에서 실행되나요? Unraid와 TrueNAS SCALE에서는 흔한 경우입니다. 이때 Plex는 자체 컨테이너 안의 폴더 경로(예: /data/Photos)를 보여 줍니다. 도우미에는 서버상의 폴더 경로(예: /mnt/media/Photos)가 필요합니다. 두 경로를 찾는 방법(영어).

도우미를 설치하는 방법은 세 가지입니다. 방법 B는 모든 시스템에서 작동합니다. Unraid, Synology, TrueNAS SCALE에서는 방법 A와 C 대신 아래의 시스템별 안내를 따르세요.

명령어는 서버의 터미널에 입력합니다. Mac에서는 터미널 앱, Windows에서는 PowerShell, Linux에서는 터미널 프로그램을 사용하거나 다른 컴퓨터에서 SSH로 접속합니다. 상자 안의 명령어에는 복사 버튼이 있습니다. Docker가 “permission denied”라고 응답하면 모든 docker 명령어 앞에 sudo를 붙이세요.

A. 명령어 하나로 빠름

Linux 컴퓨터나 서버, 그리고 Docker Desktop을 설치한 Mac에서 사용할 수 있습니다. Windows, Unraid, TrueNAS SCALE에서는 사용할 수 없습니다.

서버의 터미널에 다음 명령어를 붙여 넣으세요:

curl -fsSL https://phlixapp.com/camera-upload/install.sh | sh

설치 프로그램은 Docker를 확인하고 업로드 폴더를 묻습니다. 그런 다음 홈 폴더에 phlix-camera-upload라는 새 폴더를 만들어 Compose 파일(docker-compose.yml)을 저장하고, 도우미를 시작한 뒤 점검을 실행합니다. 모두 정상이면 Phlix Camera Upload is running.을 출력하고, 그 아래에 도우미 상태 페이지의 주소와 함께 Status page:로 시작하는 줄을 출력합니다.

이 스크립트는 sudo를 사용하는 일도, Plex를 변경하는 일도, 사진을 삭제하는 일도 없습니다. 실행하기 전에 스크립트를 읽어 볼 수 있으며, 아무것도 변경하지 않는 --dry-run으로 먼저 시험해 볼 수도 있습니다:

curl -fsSL https://phlixapp.com/camera-upload/install.sh | sh -s -- --dry-run

도우미를 업데이트하려면 언제든지 설치 프로그램을 다시 실행하세요. 같은 스크립트가 GitHub 저장소에도 있습니다.

B. AI 어시스턴트에게 맡기기

SETUP-WITH-AI.md 파일에는 AI 어시스턴트를 위해 작성된 전체 안내가 담겨 있습니다. Plex 라이브러리 폴더를 찾는 방법, 도우미를 설치하고 점검하는 방법, 문제가 생겼을 때 해결하는 방법이 들어 있습니다. 어시스턴트는 도우미 자체 폴더 밖의 것을 변경하기 전에 먼저 묻습니다. 파일은 영어로 되어 있지만, 어시스턴트는 한국어로 대화할 수 있습니다.

서버에서 명령을 실행할 수 있는 어시스턴트(Claude Code, Codex, Gemini CLI, Cursor 및 비슷한 도구)를 사용한다면, 서버의 비어 있는 새 폴더에서 다음을 실행하세요:

curl -fsSLO https://phlixapp.com/camera-upload/SETUP-WITH-AI.md

그런 다음 그 폴더에서 어시스턴트를 시작하고 이렇게 말하세요: SETUP-WITH-AI.md의 안내대로 진행해 주세요

Claude Code에서는 터미널에서 한 번만 실행해 설정을 스킬로 추가할 수도 있습니다:

claude plugin marketplace add jrl8085/phlix-camera-upload
claude plugin install phlix-camera-upload@phlix

그런 다음 서버에서 Claude Code를 시작하고 이렇게 말하세요: 이 서버에 Phlix Camera Upload를 설정해 주세요

ChatGPT나 Claude 앱 같은 채팅 어시스턴트를 사용한다면 SETUP-WITH-AI.md 파일을 전달하고 한 단계씩 차근차근 안내해 주세요라고 말하세요. 어시스턴트가 명령어를 하나씩 알려 주면 서버에서 실행하고, 출력된 내용을 다시 붙여 넣으면 됩니다.

C. Docker Compose로 직접 설치하기

Linux, Mac 또는 Windows PC에서 모든 단계를 직접 확인하고 싶은 분을 위한 방법입니다. 6단계로 되어 있으며, 수정할 줄은 하나뿐입니다.

  1. 사진을 소유한 사용자로 업로드 폴더를 만드세요. 도우미는 이 폴더의 소유자로 파일을 저장합니다. 
    mkdir "/mnt/media/Photos/Camera Uploads"
  2. 도우미용 폴더를 만들고 그 폴더로 이동하세요. 
    mkdir phlix-camera-upload
cd phlix-camera-upload
  3. Compose 파일 docker-compose.yml을 다운로드하세요. Docker에 도우미를 실행하는 방법을 알려 주는 작은 텍스트 파일입니다. 
    curl -fsSLO https://phlixapp.com/camera-upload/docker-compose.yml
  4. 텍스트 편집기에서 docker-compose.yml을 여세요. CHANGE THE NEXT LINE 주석을 찾으세요. 그 아래 줄에서 /CHANGE/THIS/Photos/Camera Uploads를 업로드 폴더 경로로 바꾸세요. 파일을 저장하세요.
  5. 도우미를 시작하세요. 처음에는 Docker가 이미지를 다운로드합니다. 이미지는 Docker용으로 패키징된 도우미입니다. 
    docker compose up -d
  6. 모든 것이 정상인지 도우미에게 확인하세요. 
    docker exec phlix-camera-upload python -m phlix_upload doctor
다운로드되는 그대로의 Compose 파일

파일 안의 주석은 영어로 되어 있습니다. CHANGE THE NEXT LINE 아래의 줄만 수정하세요.

# Phlix Camera Upload
#
# This file starts the helper that receives the photos and videos the Phlix
# app uploads from your iPhone or iPad, and writes them into a folder of your
# Plex photo library.
#
# How to use this file:
#   1. Change the one line marked CHANGE THE NEXT LINE below.
#   2. In the folder that holds this file, run:  docker compose up -d
#   3. Open https://YOUR-SERVER:7459 in a browser to check that it runs.
#      The browser warns about the certificate. That is expected.
#
# If something does not work, ask the helper what is wrong:
#   docker exec phlix-camera-upload python -m phlix_upload doctor
#
# Setup guide: https://phlixapp.com/camera-upload/
# If the app cannot find the helper:
#   https://github.com/jrl8085/phlix-camera-upload/blob/main/NETWORKING.md

services:
  phlix-camera-upload:
    image: ghcr.io/jrl8085/phlix-camera-upload:1
    container_name: phlix-camera-upload

    # Start again by itself when the server or Docker restarts.
    restart: unless-stopped

    # The Phlix app looks for the helper on port 7459 of your server.
    ports:
      - "7459:7459"

    volumes:
      # Your upload folder: the folder on this server where the photos go.
      #
      # It must be inside a folder that one of your Plex photo libraries
      # includes. If it is not, Plex never shows the photos.
      #
      # Make the folder before you start the helper. Docker refuses to start
      # the helper if the folder is missing. The helper writes files as the
      # user who owns the folder.
      #
      # Write the path as it is on the server itself. If Plex runs in Docker,
      # do not use the path from inside the Plex container.
      #
      # Examples:
      #   Linux      /mnt/media/Photos/Camera Uploads
      #   Synology   /volume1/photo/Camera Uploads
      #   TrueNAS    /mnt/tank/media/Photos/Camera Uploads
      #   Mac        /Users/you/Pictures/Camera Uploads
      #   Windows    C:\Users\you\Pictures\Camera Uploads
      #
      # Spaces in the path are fine. If the path has a "#" after a space, or
      # a ":" before a space, put the whole path in 'single quotes'.
      - type: bind
        # CHANGE THE NEXT LINE. Keep "source: " and write your folder after it.
        source: /CHANGE/THIS/Photos/Camera Uploads
        target: /photos
        bind:
          create_host_path: false

      # The helper's own data: the list of paired phones, the list of files
      # it has received, and its certificate. No photos are kept here.
      # Docker makes a folder named "config" next to this file. Keep it: if
      # it is lost, every phone has to pair again.
      # If your tool has no "next to this file" (TrueNAS, Portainer), write a
      # full path in place of ./config, for example:
      #   /mnt/tank/apps/phlix-camera-upload:/config
      - ./config:/config

    # Lets the helper find Plex Media Server on this machine.
    extra_hosts:
      - "host.docker.internal:host-gateway"

    # The helper can never gain more rights than it was started with.
    security_opt:
      - "no-new-privileges:true"

    # Optional settings. The helper works without any of them.
    #
    # To use one, remove the "# " in front of "environment:" and in front of
    # the setting you want. Leave the other spaces as they are. Then run
    # "docker compose up -d" again.
    #
    # environment:
    #   # Where Plex Media Server is. Set this if the helper's status page
    #   # says "Plex Media Server: Not found", or to make sure that the helper
    #   # asks your own server and no other.
    #   PLEX_URL: "http://192.168.1.10:32400"
    #
    #   # Write files as this user and group. Without these, the helper uses
    #   # the owner of the upload folder.
    #   PUID: "1000"
    #   PGID: "1000"
    #
    #   # Permissions for new files and folders. With 022, other users may
    #   # read them. With 002, the group may also change them.
    #   UMASK: "022"
    #
    #   # The name that the app and the status page show for this helper.
    #   NAME: "Phlix Camera Upload"
    #
    #   # Who may pair. auto: the owner of the Plex server pairs without a
    #   # code and everyone else types the pairing code. code: everyone types
    #   # the code. plex: only the owner of the Plex server may pair.
    #   PAIRING: "auto"
    #
    #   # Your own pairing code, in place of the one the helper makes. Write
    #   # at least 6 letters or digits between the quotes.
    #   PAIRING_CODE: ""
    #
    #   # The folders the helper makes inside the upload folder. You can use
    #   # {device}, {year}, {month} and {day}.
    #   PATH_TEMPLATE: "{device}/{year}/{year}-{month}"
    #
    #   # Refuse uploads that would leave less than this many GB free. Uploads
    #   # that are still arriving count too.
    #   MIN_FREE_GB: "2"
    #
    #   # The largest single file the helper accepts, in GB.
    #   MAX_UPLOAD_GB: "50"
    #
    #   # More file types to accept, besides the usual photo and video types.
    #   # Separate them with commas.
    #   EXTRA_EXTENSIONS: "insp,lrv"
    #
    #   # How much the log says: debug, info, warning or error.
    #   LOG_LEVEL: "info"
    #
    #   # Write "off" only if your own reverse proxy adds HTTPS in front of
    #   # the helper. Phlix talks HTTPS only: with "off" and no such proxy,
    #   # the app cannot use the helper.
    #   TLS: "on"
    #
    #   # Your own certificate and its key, as paths inside the container.
    #   # Set both. A file you put in the config folder is at /config/...
    #   TLS_CERT: "/config/my-cert.pem"
    #   TLS_KEY: "/config/my-key.pem"
    #
    # PORT, BIND, UPLOAD_DIR and CONFIG_DIR exist too. With Docker you do not
    # need them. To use another port on your server, change only the first
    # number in the "ports" line above, for example "8443:7459". The app
    # looks for port 7459 by itself, so with another port you type the
    # helper's address into the app.

Unraid, Synology, TrueNAS SCALE 및 Windows

  • Unraid에는 Docker Compose가 없습니다. Plex 사진 라이브러리에 포함된 공유 폴더 안에 업로드 폴더를 만들고, chown 99:100으로 Unraid 기본 사용자에게 소유권을 넘긴 다음, 아래 명령어로 템플릿을 다운로드하세요. 그런 다음 Docker 탭에서 Add Container를 선택하고 phlix-camera-upload를 고르세요. Unraid 설치 단계(영어). 
    mkdir "/mnt/user/Photos/Camera Uploads"
chown 99:100 "/mnt/user/Photos/Camera Uploads"
    wget -O /boot/config/plugins/dockerMan/templates-user/my-phlix-camera-upload.xml https://raw.githubusercontent.com/jrl8085/phlix-camera-upload/main/unraid/phlix-camera-upload.xml
  • Synology: Container Manager에서 phlix-camera-upload라는 이름의 프로젝트를 만들고 docker-compose.yml의 내용을 붙여 넣으세요. 업로드 폴더는 /volume1/photo/Camera Uploads처럼 전체 경로로 적으세요. Synology 설치 단계(영어).
  • TrueNAS SCALE: 방법 A는 사용하지 마세요. Apps › Discover Apps로 이동해 Install via YAML을 선택하고, Compose 파일을 붙여 넣은 다음 전체 경로를 입력하세요. TrueNAS SCALE 설치 단계(영어).
  • Docker Desktop을 사용하는 Mac 또는 Windows PC: Windows에서는 방법 B나 C를 사용하고, 이 페이지에 curl이라고 적힌 곳에는 curl.exe를 입력하세요. 업로드는 Docker Desktop이 실행 중이고 컴퓨터가 잠자기 상태가 아닐 때만 진행됩니다. Mac 및 Windows 참고 사항(영어).

실행 확인하기

집 네트워크에 있는 다른 기기의 브라우저에서 도우미의 상태 페이지를 여세요. SERVER는 서버 주소로 바꾸세요(예: https://192.168.1.10:7459):

https://SERVER:7459

브라우저에 연결이 비공개 연결이 아니라는 경고가 표시됩니다. 이는 정상입니다. 가정용 서버에는 인증 기관이 보증할 수 있는 공개 이름이 없기 때문에 도우미가 자체 인증서를 만듭니다. 그대로 페이지로 이동하세요. Phlix는 브라우저의 확인에 의존하지 않고, 페어링할 때 도우미의 인증서를 정확히 기억합니다.

페이지에 Upload folder: Ready와 Plex Media Server: Found가 표시되어야 합니다. 다른 내용이 표시되면 doctor 명령어가 해결 방법을 알려 줍니다:

docker exec phlix-camera-upload python -m phlix_upload doctor

OK       223.6 GB free on the upload disk.
OK       Plex Media Server found: its owner can pair from Phlix without a code.
OK       1 paired, 37 files stored (33.0 MB).

PROBLEM으로 시작하는 줄 다음에는 Fix:로 시작하는 줄이 이어집니다.

Plex 설정 하나. Plex는 스캔을 마친 후에야 새 파일을 표시합니다. Plex 계정이 서버의 소유자라면 사진이 도착한 후 Phlix가 Plex에 스캔을 요청합니다. 집의 다른 모든 사용자를 위해, 그리고 확실히 하기 위해 Plex에서 설정 › 라이브러리 › 내 라이브러리를 자동으로 스캔을 켜세요. 기본적으로 꺼져 있습니다.

2단계: iPhone 연결하기

  1. iPhone이나 iPad를 집 Wi-Fi에 연결하세요.
  2. Phlix를 열고 설정 › 카메라 업로드로 이동하세요. 설정에 카메라 업로드 항목이 없다면 사용 중인 Phlix가 1.0.21보다 이전 버전입니다. 버전 번호는 설정의 버전 항목에서 확인할 수 있습니다.
  3. 도우미 찾기를 탭한 다음 네트워크 확인을 탭하세요. Phlix가 Plex 서버의 주소에서 도우미를 찾습니다. 도우미를 찾을 때까지는 아무것도 켜지지 않고 아무것도 업로드되지 않습니다. iOS에서 Phlix가 로컬 네트워크의 기기를 찾도록 허용할지 물으면 허용하세요.
  4. Phlix에 도우미를 찾았습니다라고 표시되면 이 기기의 폴더 이름(예: “지민의 iPhone”)을 정하고 연결을 탭하세요. 이 기기를 이전에 이 도우미에 연결한 적이 있다면 Phlix가 보여 주는 이름을 그대로 두세요. 그러면 기기가 기존 폴더를 계속 사용합니다. 다른 이름으로 바꾸면 이 기기의 새 사진은 그 이름의 폴더에 들어갑니다.
  5. 이제 Phlix에 페어링 코드를 입력하세요라는 화면이 나타나면 도우미의 페어링 코드를 입력하고 페어링을 탭하세요. 개인 Plex 계정이 있는 가족 구성원에게 이 단계가 표시됩니다. 코드를 찾는 위치는 아래의 코드가 필요한 사람에서 확인하세요.
  6. Phlix에 연결됨이 표시됩니다. 백업할 항목으로 이 기기의 모든 항목 또는 새로운 사진만을 선택하고 카메라 업로드 켜기를 탭하세요.
  7. iOS에서 Phlix가 사진을 읽어도 되는지 묻습니다. 모든 사진을 백업할 수 있도록 ‘전체 접근 허용’을 선택하세요.

초록색 점과 함께 도우미 이름이 들어간 …에 연결됨이 표시되면 연결 상태가 좋은 것입니다. 회색은 집 밖에 있다는 뜻이며, 이때 Phlix는 기다립니다. 주황색은 확인이 필요한 문제가 있다는 뜻이며, 화면에 그 내용이 표시됩니다.

페어링 코드가 필요한 사람

  • Plex 서버의 소유자: 도우미의 상태 페이지에 Plex Media Server: Found가 표시되어 있으면 Phlix는 코드 없이 페어링합니다. 앱이 Plex 서버에서 받은 수명이 짧은 토큰을 도우미에게 보여 주면, 도우미는 이 토큰이 서버 소유자의 것인지 Plex에 확인한 다음 토큰을 잊어버립니다.
  • 그 외의 모든 사용자(예: 개인 Plex 계정이 있는 가족 구성원)는 도우미의 페어링 코드를 입력합니다. 서버 소유자는 이 명령어로 코드를 찾거나, 도우미가 시작할 때마다 남기는 로그에서 찾을 수 있습니다. 대소문자, 공백, 대시는 상관없습니다: 
    docker exec phlix-camera-upload python -m phlix_upload code

Phlix에 도우미를 찾지 못했습니다라고 표시되면 카메라 업로드는 꺼진 상태로 유지되며, 어디로도 아무것도 전송되지 않습니다. 앱이 도우미를 찾지 못하는 경우(영어).

그다음에 일어나는 일

  • Phlix를 열어 두면 업로드가 바로 시작되고 Wi-Fi가 허용하는 만큼 빠르게 진행됩니다. 처음에 대량으로 백업할 때는 휴대폰을 충전기에 연결하고 카메라 업로드 화면을 열어 두면 더 빠르게 진행됩니다.
  • Phlix를 닫으면 iOS가 주로 휴대폰을 충전하는 동안 짧게 여러 번에 걸쳐 작업을 이어 가도록 허용합니다. iOS는 모든 앱을 이렇게 처리하므로, 보관함이 크면 백그라운드에서 며칠이 걸립니다. 새로 찍은 사진은 그 뒤로 자동으로 업로드됩니다.
  • 집 밖에서는 아무것도 전송되지 않으며, Phlix는 서버를 찾지도 않습니다. 휴대폰이 집 Wi-Fi에 다시 연결되면 백업이 계속됩니다.
  • 모든 항목이 백업되면 화면에 모든 항목 백업됨이라고 표시됩니다. 알림도 받으려면 백업 완료 시 알림을 켜세요.
  • 백업된 사진 수는 서버에 실제로 있는 사진 수입니다. Phlix는 카메라 업로드 화면을 열 때마다, 화면이 열려 있는 동안에는 30초마다, 그리고 연결 확인을 탭하면 즉시 도우미에게 어떤 사진이 업로드 폴더에 있는지 묻습니다. 서버에서 파일이 삭제되었다면 Phlix가 그 사진을 다시 업로드합니다.

Phlix는 사진 보관함에 있는 사진과 비디오를 그 시점에 사진 앱에 보이는 모습 그대로 업로드합니다. 비디오는 선택 사항이며(비디오 포함), 스크린샷은 스크린샷 포함을 켜지 않으면 제외됩니다. Live Photo는 스틸 사진으로 업로드됩니다. 가려진 사진, 공유 앨범, 컴퓨터에서 동기화한 사진은 업로드되지 않습니다.

사진이 저장되는 위치

휴대폰이나 태블릿마다 업로드 폴더 안에 자체 폴더가 있으며, 그 안에 연도별, 월별 폴더가 있습니다:

Camera Uploads/
  Anna's iPhone/
    2026/
      2026-11/
        IMG_1234.HEIC
        IMG_1235.MOV
  Ben's iPad/
    2026/
      2026-10/
  • 연도와 월은 사진 자체의 날짜를 따릅니다. 파일 이름은 휴대폰에서 쓰던 이름이 그대로 유지됩니다.
  • 이름이 같은 서로 다른 사진 두 장은 모두 보관됩니다. 어떤 파일도 덮어쓰지 않습니다.
  • 두 휴대폰에 있는 같은 사진은 한 번만 저장됩니다.

개인정보 보호 및 보안

  • 사진은 집 네트워크 안에 머뭅니다. 휴대폰이 사진을 서버로 바로 전송합니다. 개발자인 Phlix는 사진을 절대 받지 않으며 사진에 접근할 수도 없습니다. 도우미는 인터넷의 어떤 곳에도 접속하지 않으며, 유일하게 연결하는 대상은 직접 운영하는 Plex Media Server입니다.
  • 연결은 암호화됩니다. 휴대폰을 페어링할 때 Phlix는 도우미의 인증서를 정확히 기억합니다. 그 후로는 그 인증서를 제시하는 서버와만 통신합니다.
  • 페어링에는 증명이 필요합니다. Plex 서버 소유자는 Plex를 통해 소유자임을 증명하며, 도우미는 Plex 토큰을 절대 저장하지 않습니다. 그 외의 모든 사용자는 페어링 코드가 필요하며, 도우미는 코드를 추측하려는 사람의 시도를 지연시킵니다.
  • 페어링된 휴대폰은 추가만 할 수 있습니다. 도우미는 저장된 파일을 나열하거나, 읽거나, 다운로드하거나, 덮어쓰거나, 삭제하는 방법을 제공하지 않습니다. 사진과 비디오 파일만 받습니다.
  • 코드를 직접 확인할 수 있습니다. 도우미의 소스 코드는 GitHub에 공개되어 있으며, 보안 참고 사항도 함께 있습니다. 자세한 설명은 개인정보 처리방침(영어)에 있습니다.

도움말 및 문제 해결

먼저 도우미의 자체 점검을 실행하세요. 설치 상태를 테스트하고 잘못된 부분을 고치는 방법을 알려 줍니다:

docker exec phlix-camera-upload python -m phlix_upload doctor

Phlix의 카메라 업로드 화면에는 발견된 문제가 표시되며, 연결 확인을 탭하면 다시 시도합니다. 문제마다 전체 가이드(영어)에 별도의 섹션이 있습니다:

  • 앱이 도우미를 찾지 못함
  • Plex에 사진이 표시되지 않음
  • 페어링이 되지 않음
  • 파일 소유자가 잘못되었거나 도우미가 파일을 쓸 수 없음
  • 도우미가 시작되지 않음
  • 네트워크 도움말: 방화벽, 게스트 Wi-Fi, VPN, Docker에서 실행하는 Plex
  • 나중에 변경하기: 도우미 업데이트, 이동, 제거

화면에 도우미 업데이트 필요라고 표시되면 서버의 도우미가 버전 1.0.2보다 이전 버전이어서, 어떤 사진을 아직 가지고 있는지 Phlix에 알려 줄 수 없습니다. 도우미를 업데이트하세요(업데이트 단계는 영어로 되어 있습니다). 카메라 업로드 화면의 도우미 버전 항목에 실행 중인 버전이 표시됩니다.

GitHub에 있는 한국어 도우미 안내: README. 도우미 관련 문제는 GitHub Issues에, 그 밖의 문의는 지원 페이지에 남겨 주세요.

자주 묻는 질문

카메라 업로드는 베타 기능인가요?

네. 카메라 업로드는 Phlix 1.0.21 이상의 베타 기능입니다. 대체할 수 없는 항목은 따로 백업해 두시고, 문제가 생기면 알려 주세요. Phlix에서 설정을 열고 피드백 보내기를 탭하면 됩니다.

Plex 자체의 Camera Upload는 어떻게 되었나요?

Plex는 2021년 3월에 자체 Camera Upload 기능의 지원을 종료한다고 발표했으며, 제거 시점은 2021년 6월로 예정되어 있었습니다. Phlix의 카메라 업로드는 독립 앱의 별개 기능으로, 직접 운영하는 서버의 도우미를 통해 Plex 사진 라이브러리의 폴더로 사진을 복사합니다.

iPhone에서 사진이 삭제되나요?

아니요. Phlix는 사진과 비디오를 서버로 복사합니다. 사진 보관함에 있는 어떤 항목도 절대 삭제하거나 변경하지 않습니다.

집 밖이나 셀룰러 데이터로도 작동하나요?

아니요, 의도적으로 그렇게 설계되었습니다. Phlix는 휴대폰이 집 Wi-Fi에 연결되어 있을 때만 업로드합니다. 집 밖에서는 아무것도 전송하지 않으며 서버를 찾지도 않습니다. 여행 중에 찍은 사진은 집에 돌아오면 업로드됩니다.

Plex Pass가 필요한가요?

아니요. 도우미는 Plex 사진 라이브러리의 폴더에 일반 파일을 저장하므로 모든 Plex Media Server에서 작동합니다.

비용은 얼마인가요?

서버용 도우미는 무료입니다. 앱에서는 처음 100회의 업로드가 무료이며, 나머지는 Phlix Pro가 업로드합니다.

가족 모두가 사용할 수 있나요?

네. iPhone과 iPad는 각각 따로 페어링하며 각자 자체 폴더를 받습니다. Plex 서버 소유자는 코드 없이 페어링하고, 그 외의 모든 사용자는 도우미의 페어링 코드를 입력합니다. 두 휴대폰에 같은 사진이 있으면 서버에는 한 번만 저장됩니다.

동기화인가요? 사진을 삭제하면 어떻게 되나요?

휴대폰에서 서버로 가는 단방향 복사입니다. 휴대폰에서 사진을 삭제해도 서버의 사본은 그대로 남으며, 휴대폰으로 돌아오는 것은 아무것도 없습니다. 서버에서 파일을 삭제했는데 사진이 아직 휴대폰에 있으면 Phlix가 다시 업로드합니다.

iCloud 사진과 함께 작동하나요?

네. Phlix는 iOS가 사진을 어디에 보관하든 사진 보관함의 사진을 읽습니다. ‘iPhone 저장 공간 최적화’를 사용하는 경우, Phlix가 요청하면 iOS가 iCloud에서 원본 크기의 사진을 다운로드합니다. 공유 앨범은 포함되지 않습니다.

Phlix는 Plex에서 만든 앱인가요?

아니요. Phlix는 Plex Media Server와 함께 작동하는 독립 앱입니다. Plex, Inc.와 제휴 관계가 없으며 Plex, Inc.의 보증이나 후원을 받지 않습니다.

카메라 업로드(베타)는 집 Wi-Fi에서만 카메라 롤을 개인 서버에 백업합니다. 또한 Phlix는 서버의 어떤 사진이든 사진 앱에 저장하고, 라이브러리 전체를 날짜 타임라인으로 보여 주며, TV에서 보는 슬라이드쇼도 제공합니다.
